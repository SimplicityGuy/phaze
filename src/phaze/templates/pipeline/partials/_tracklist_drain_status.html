Fed by GET /pipeline/tracklist-drain-status, which calls phaze.tasks.tracklist_drain.tracklist_drain_status DIRECTLY (a request-free read, per that function's own docstring: "the admin UI needs how-much-is-left far more often than it needs a run, and answering that must never cost budget"). This fragment renders exactly the fields that function returns -- no second funnel is computed here. HONESTY RULES this fragment exists to enforce (see the bead): * dedup is a ~3% lever, not a big multiplier -- `status.collapse_ratio` is shown as a plain number (files per lookup), with the no-dedup comparison alongside it, so "collapse ratio 1.03" cannot be misread as "97% savings". * the ETA divides by the SAME ceiling every other projection in this molecule uses (DAILY_LOOKUP_CEILING) and shows the without-dedup-or-cache figure next to it, so neither number can be read as more optimistic than the other actually is. * operator-flagged sets are counted separately (`flagged_queued`) from the funnel, since a flag changes ORDER, not the total amount of work. phaze-6nrrf ARM/DISARM ROW: `arm` is the durable TracklistDrainArmState row (services. tracklist_drain_arm.get_arm_state) -- the SAME row the continuous-drain cron (tasks.tracklist_drain_control.continue_armed_tracklist_drain) reads, so this is never a second, drifting status surface. Arm/Disarm POST their own endpoints and re-render this WHOLE fragment (hx-swap="outerHTML" on this div's own id), so the badge, the reason, and the funnel numbers below always agree with each other and with whatever the cron just did. #}
