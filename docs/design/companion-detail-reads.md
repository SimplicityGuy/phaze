# Shared companion detail reads

Date: 2026-10-10. Bead: phaze-19307. Epic: phaze-kf7jr.

`services/companion_details.py` reads stored inventory and evidence into the bounded contracts in `schemas/companion_details.py`. `routers/record.py:build_file_record_context` adds `companion_details` for both the full file page and drawer. The viewing bead phaze-517k9 owns their visual sections/actions and served callers of the new read routes; its temporary route-reachability ledger entries must be removed when those callers land or endpoints are deliberately consolidated.

Current FileCompanion links remain visible even when no provider object or captured text exists. Filenames, type and location come from inventoried FileRecord rows. NULL derivation fields mean historical_unknown; current paths do not reconstruct link-method provenance. Source history remains visible through exact candidate, current selection or selection-event references. Deleted source filenames are unavailable; retained original file/source identity is honest history rather than an invented name.

Pages use validated offset/limit values (offset 0–100000, limit 1–50), with unique UUID ties for inventory/source order and retrieval-time plus observation UUID ties for stored content history. Offset pages describe a read snapshot; concurrent new rows may move page positions. Current bound-source IDs and exact recorded target associations are unioned before source paging. The backfill bead adds the source-file binding index. Summary SQL selects scalar/count fields, at most 512 decoded characters, and bounded reasons. It does not transfer full source text or whole observation payloads for every history/source row.

`latest_stored_content` is the newest retained immutable observation in retrieval-time/UUID order. It does not assert the latest physical read or callback outcome: semantic observations may deduplicate. `latest_received_attempt` is independent, normalized from an optional injected attempt reader. Its server ordinal describes receipt order; attempted/acquired times remain distinct. With no reader or no authorized attempt rows, attempt history is unknown. The acquisition/backfill bead supplies the real attempt reader; the assembled viewing integration must inject it into the shared context, not leave a permanent unknown stub.

Only two supported selected authority kinds are rendered, tracklist and release_metadata; other stored kinds remain history/membership evidence without expanding this authority list. A selected observation stays pinned when missing, stale or unlinked. Availability is a separate read state. The overview uses narrow authority reads; detailed selected tracks reuse `get_selected_recording_source`, including reviewed CUE target mapping. Intrinsic source rows and target-projected rows stay distinct.

Observation/text membership requires an owned current link or embedded/self source, or the requested file's exact candidate/selection/event reference to that observation. Historical object membership alone grants no access to later content imported for another target or agent. Reverse links require equal source/media agent IDs. Detail reads enqueue nothing and perform no agent/network/filesystem acquisition.

One authorized observation detail pages intrinsic tracks and release facts through PostgreSQL JSON paths, exposes conflicts and bounded parse/provenance evidence, and pages selected projected tracks separately. Lazy stored text uses SQL substring with character offset 0–262144 and length 1–32768; it returns encoding, total characters, original read-truncation flag and a continuation offset. Missing original text is NULL, not an empty successful source. Snapshot parse incompleteness remains distinct from captured read truncation.

The pure read seams have synthetic PostgreSQL tests for linked-but-unparsed files, multiple sources/targets, exact historical membership, source deletion/status changes, review pinning, conflicts/original values, reverse ownership, finite query/text bounds and deduplicated content versus latest received attempts. Existing page/drawer parity tests remain applicable. Future consumer integration owns tag/Discogs/CUE authority cutover; these reads do not manufacture compatibility Tracklist rows or rewrite embedded metadata.
