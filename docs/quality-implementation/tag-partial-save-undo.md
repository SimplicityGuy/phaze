# Partial tag-save Undo recovery

A mutagen save can write ID3v2 bytes and subsequently fail updating the ID3v1 tail. The agent now reports `save_failed` specifically for an exception inside `audio.save()`. The original snapshot remains eligible as the oldest Undo anchor, including after a later successful retry. Loading, containment, snapshot and tag-preparation failures remain ordinary `failed`, excluded from Undo. The existing executor ownership and durable snapshot acknowledgement remain unchanged.

The status column is plain text and needs no schema migration. Deploy the controller and agent together, or controller first: older controllers reject the new enum value rather than silently misclassifying it. Drain older-agent tag jobs before treating the fix as available. Historical `failed` rows cannot safely be backfilled from a digest or snapshot alone: neither proves save was attempted, so these retain their existing behavior and require manual audit recovery if affected. A save exception can also occur before bytes move; offering Undo is deliberately conservative once save was attempted.

Regression tests use synthetic MP3 media, the real mutagen ID3v2 write with failure injected only in the subsequent ID3v1 operation, authenticated ASGI callbacks, PostgreSQL audit/hash reads, actual Undo/retry routes, and production broker serialization with simulated delivery. The fixture uses one outer transaction, so a synthetic first-attempt timestamp establishes chronology across savepoint commits; column queries bypass the identity map but do not prove visibility on an independently committed connection.
